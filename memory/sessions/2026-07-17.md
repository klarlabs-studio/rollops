## Decisions Made

- **`manifestFrom`: reference manifests (path / kustomize / helm) as an alternative to inline `spec.target.spec.manifest`** (issue #57). Reasoning: kustomize/Helm users were forced to render-and-paste, keeping a drift-prone second source of truth — the one thing that made Rollops feel *heavier* than ArgoCD/Flux for exactly the migration it targets.
- **Four design forks, all chosen by the operator:**
  - **Root = the config file's own directory** (relative paths resolve there, not the repo root) — matches the intuition of the #57 examples.
  - **Schema = add `manifestFrom` AND keep the flat keys** (`helm`/`kustomize`/`manifest`/`oci`/`bucket`) working — non-breaking; a shipped example + tests depend on the flat keys.
  - **Drift = checksum the *rendered output* for referenced sources** (not the spec text) — so editing a referenced kustomize/helm/path file reconciles even under shallow verification. Inline unchanged.
  - **Rendering = keep shelling out to `kubectl kustomize` / `helm template`** (the target already does), NOT a Go kustomize/Helm SDK — those pull `client-go`/`k8s.io/api`, which violates the no-Kubernetes-in-core constraint (AGENTS.md, `kubernetes.go` pkg doc).
- **Surprising finding:** most of the renderer already existed (`internal/target/kubernetes/render.go` renders helm/kustomize/oci/bucket; image digest-pin applies post-render). The real gap was **path-threading** — local relative paths resolved against the daemon CWD, not the git checkout, because nothing carried the checkout root down. Fix = `Root string` on `pt.Manifest` (`json:"-"`, not persisted, excluded from checksum), threaded `watch → reconcile → engine → target`; CLI uses `filepath.Dir(configArg)`. `Plan(ctx,c)` stayed interface-stable by carrying root via context; `Apply` via `ApplyRequest.Root`.
- **Rollback of a referenced source = restore the *captured rendered bytes*, not re-render** (issue #59 enhancement). Reasoning: re-rendering the prior spec against the current checkout (a) fails on the manual CLI/web-UI/MCP/HTTP-API/gRPC path, which has no checkout (empty Root), and (b) is semantically wrong even on the daemon — if the referenced files changed since deploy, "rollback" would deploy something never previously applied. Fix = persist `pt.Manifest.Rendered` (JSON `omitempty`, rides the existing desired-manifest blob — **no store schema change**); `Apply`/`Diff` prefer it; a rollback restores exactly what was deployed, root-independent.

## What Went Wrong

- **Release CHANGELOG PR (#61) got stuck.** `ci.yml` has `paths-ignore: ["**.md", "docs/**", "LICENSE"]`, so a docs-only PR *skips* the CI jobs — but `ci / Test|Build|Lint|Security` are *required* branch-protection checks, so they never report and the PR is permanently `BLOCKED`. Resolved by **admin-merge** (operator-authorized). Root cause: the maintainer normally bundles the CHANGELOG into a code commit; a standalone changelog PR is the anomaly. (Candidate AGENTS.md failure-mode note — see below.)
- **`v0.25.0` was tagged without a CHANGELOG entry** — backfilled it during this release.
- gopls kept emitting spurious "cannot find package / unused import" diagnostics because it's rooted at the session cwd (a *different* repo), not the rollops module. Ignored — real `go build ./...` / `go test ./...` were always clean. Verify Go work by building in the module, never by trusting the IDE diagnostics here.
